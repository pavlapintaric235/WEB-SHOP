It saves ranked predictions and the embeddings needed for a later fixed-query registration curve.

## What prevents the 30-scene result today

- The Windows project environment has OpenCV `5.0.0`, Streamlit `1.65.0`, and local SigLIP2 weights, but PyTorch is `2.14.1+cpu`, ONNX Runtime exposes only Azure/CPU providers, and `nvidia-smi` is unavailable. It cannot execute the prescribed TensorRT DINO plus CUDA SigLIP2 pass.
- A fresh connected RunPod `get_pod` read at 2026-10-20 14:45 UTC showed existing Pod `1ohwvb6g1jia9f` **RUNNING** after the user started it, with one `NVIDIA B300 SXM6 AC MIG 1g.34gb`, listed GPU rate `$0.50/hour`, 50 GB persistent `/workspace` volume disk, and 30 GB container disk. The user explicitly asked to leave it running. However, its system log repeatedly says `error creating container: cant create container; network must exist`, the container log has no lines, and `runtime` is null. The metadata does **not** prove that a usable container, mounted files, NVIDIA models or TensorRT custom plugins are present. The prior DINO run initially failed because `MultiscaleDeformableAttnPlugin_TRT` was not registered; a later domain-remapped TensorRT run succeeded on other scenes. This v3 runner is compatible with that remapped model **by code and expected paths only** until a live preflight succeeds. Do not infer scene predictions from this Pod status.
- There is no imported 30-scene `predictions.csv`, no detector overlays for those scenes, and no scene recognition accuracy. The one saved `IMG_4857` annotation has two identical boxes in the upper-left part of the full-resolution photo; it must be corrected before any scoring. No SKU identities have been owner-confirmed.
- SigLIP2 scores are cosine rankings, not calibrated acceptance probabilities. The runner does not invent an unknown threshold; every model suggestion remains unaccepted until review or a separately justified acceptance rule exists.
