# Security, privacy and third-party terms

The judge sandbox uses a separate database, generated access code, separate generated owner/employee passwords, and a 30-minute access session. It refuses default local demo passwords and references outside its own data directory. It starts on loopback with CORS/XSRF protection, static serving disabled, bounded uploads and hidden uncaught error details. Judge-facing errors/exports omit operator paths and service details. None of this replaces a whole-host authentication gateway: Streamlit images and downloads use separate HTTP routes.

Only an email-restricted gateway may publish the judge copy. Never tunnel ports 8508/8509, the working data directories, RunPod SSH, or its private worker port. Do not disable XSRF to make an unverified proxy appear functional. Verify authorized WebSocket sessions and unauthorized HTTP/media/WebSocket denial before sharing a URL. Keep all private data and tunnel logs under ignored `data/`. A changing temporary URL has no uptime guarantee; use named access-controlled hosting or an arranged screen-share for continuity.

Judge setup copies fictional workbook rows and shelves only. It does not copy private product photos, masks, embeddings, checkpoints or historical scan photos. Public screenshots contain actual sandbox UI and explicit missing-photo placeholders. Publishing a private photo in a screenshot or video requires its owner's permission. A repeat registration demonstration must be disclosed as a repeat, not independent unseen-product evaluation.

Existing local-only convenience credentials are unsuitable for public hosting. Judge credentials are generated into ignored `data/judge_release/access.json`; transmit them to approved judges privately, never in README, command arguments, screenshots, logs or the video. Keep the worker token server-side. Public deployment configuration uses examples, not project-specific resource metadata. Earlier Git history may still contain project resource names/identifiers; removing a file from a new commit does not erase history. Identifiers are not access credentials. Rotate and remediate separately if a genuine secret is identified; this release does not rewrite history.
